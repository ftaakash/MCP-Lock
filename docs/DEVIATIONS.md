# Deviations from the pre-registered plan

Registered plan: [PREREG.md](../PREREG.md), OSF https://osf.io/2amj3 (plan text commit `914d2b3`, code tag `prereg-v1`).
Every departure is logged here with date, reason and effect on results, before the affected results are reported.

| # | Date | Section | Deviation | Reason | Effect |
|---|---|---|---|---|---|
| 1 | 2026-10-11 | §3.4 | *Clarification, not a change.* Replay details fixed in `docs/REPLAY.md` before any scored run: each bundle holds the records of `a` and `b` only (so the gate resolves `b`); a pre-release `b` is launched pinned, with OSV advisories limited to those published by `t`; the lock has no static tool hash when its archive is over the size cap. | The plan says "replayed as of the newer version's publish time" without fixing these mechanics. | None on what is counted; pre-releases, lock-archive failures and lookup failures are reported as counts. |
| 2 | 2026-10-11 | §3.4 | B-mcp reuses the Phase 2 tool hashes and version records instead of downloading the archives again. | The extractor code is unchanged between `extract-v2.1` and `prereg-v1` (`git diff` is empty for `census/extract_*.py` and `census/tooldefs.py`). A recomputation check on a random sample of versions is reported with the results. | None expected; the check quantifies it. |
| 3 | 2026-10-11 | §3.2, §7 | *Safety procedure tightened.* The OSV `MAL-` records and DataDog samples are now handled only inside a Docker volume, never as files on the Windows host. Only a sanitized case list (ecosystem, name, version, dates, class) leaves the container. | Microsoft Defender quarantined 5 OSV advisory JSON files (they quote malware code) from a host checkout of `ossf/malicious-packages` on 2026-10-11, 13:09–13:19. Nothing was executed. The host checkout was deleted and a Defender scan of the project folder found nothing further. | None on the corpus: the records are re-read in full at the pinned commit inside the container. |
| 4 | 2026-10-11 | §3.3 | R-S construction details. (a) Candidates were taken in seeded order; 7 eligible servers were skipped because an A1 or A2 edit could not be built and verified mechanically (`make_skipped.json`), and the next ones were used. (b) Each attack class is its own package (`@mcplock-eval/<server>-<class>`, v1 then v2), so the 40 attacks and 10 controls never interact. (c) Verdaccio stores what we publish: `_npmUser` is set by us ("GitHub Actions" for v1, A1–A3 and controls; "mallory" for A4), and attestation presence is a metadata marker whose identity is the base server's real npm attestation. (d) Verdaccio listens on 127.0.0.1:80, because the HTTP cache cannot name folders with a port on Windows. | (a) The plan did not say what to do when an edit cannot be built. (b)–(d) Mechanics not fixed by the plan. | R-S measures implementation coverage only and is outside H1 and the kill rule. The 10 negative controls were replayed as the plan allows: all 7 systems allowed all 10. |
| 5 | 2026-10-11 | §3.2 | *Clarification, not a change.* R-M replay mechanics fixed in `docs/REPLAY.md` before any scored run: affected versions are the union over all records; the class C lock is the latest listed unaffected version before `t`; a class C launch is pinned when an unpinned launch would not select the malicious version; removed versions get a stub record with signal evaluability set by the rules of §3.2. | Mechanics not fixed by the plan. | None on what is counted; pinned launches and evaluability are reported as counts. |
| 6 | 2026-10-11 | §3.2 | R-M construction outcome before any scored run. 3,349 class C cases were eligible (3,285 npm, 64 PyPI), so the cap applied: all 64 PyPI plus 336 npm by seed; 100 N cases were drawn (98 npm, 2 PyPI; 16 redraws because the registry date fell outside the window). 32 C cases cannot be replayed because no unaffected version before `t` is still listed, so no lock can be built; they are excluded and counted (`assemble_excluded.json`), leaving 368 C + 100 N = 468 primary cases. A harness bug was fixed before scoring: DataDog samples sit under temporary-folder prefixes, so the package root is now located by its `package.json` / Python project marker (S4 evaluable rose from 89 to 214 cases). | The plan did not foresee lock versions that were themselves removed, or the sample layout. | Fewer C cases than drawn; both counts reported. 35 C malicious versions are still listed on npm. They are already public in OSV/DataDog, so they are not new findings. |
